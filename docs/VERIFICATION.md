# KUBLA KHAN 2.1.13 · read-only survey, declarative plan and verified choices

The new primary flow is Survey all assignments → inspect local classifications → Run plan. It captures the visible To-do queue, previews each captured assignment and builds bounded local JSON data. It does not scan an entire account, inspect hidden questions or generate executable model code. Only the first visible question is known; later questions are re-read during execution. Start-required intros remain unknown until Run explicitly authorizes normal execution.

| Area | Supported behavior | Conservative boundary |
|---|---|---|
| Survey | Paginated same-class To-do list, up to10pages/100items; one sequential owned preview tab | No exercise Start, selection, entry, Check, question Next or media.play during survey |
| Assignment types | Videos, exercises, articles and unknown rows; dedicated Type cell takes precedence over title words | Articles are manual reading and never marked complete |
| Local plan | Strict schema with same-class unique URLs, classification, route, reason and first-visible disclosure; private JSON export | No answers, selectors, action scripts, eval, model code or arbitrary plan import |
| Execution | Stored validated ready jobs plus explicitly conditional intro inspection; every question re-read | Run requires the class assignment-list tab; no hijacking an arbitrary assignment tab |
| Single box | Existing exact solver/helper routes and verified editor readback | Existing work, unsupported output units, graphs and multiple fields remain review |
| Multiple choice | One native/ARIA/Perseus single-answer group; every option formal/readable and exactly one verified match | Unreadable distractors, duplicate equivalent options, multi-answer, disabled/mixed state or existing selection cannot be guessed |
| Factor choices | Helper-origin exact comparisons can certify factor form | Common built-in-solvable factor MC remains review even with helper configured; no blanket factor-MC support |
| Media | One independent actual video lane alongside one exercise lane | Ended observations do not certify Khan credit; survey does not start playback |

The plan schema is kubla-khan-plan-v1 with only scope, creation time and bounded item metadata. URLs must be exact same-class assignment paths; duplicates, executable/action fields and invalid ready-route combinations are rejected. Articles/review-only tasks are excluded from execution. An intro's conditional inspect-after-start route is disclosed as unknown, not claimed solved. Captured-plan execution uses the normal per-question safeguards and durable once-only Check. Direct run remains secondary for compatibility.

Survey source and preview ownership are checked after asynchronous reads/helper comparisons and immediately before navigation or closing. Manual navigation to a different same-class assignment or another site hard-stops the survey; it cannot redirect or close the user's destination. Stop generations prevent late preview creation/navigation and plan-run resurrection. Preview completion closes only the exact owned target. The original class list is not used as an exercise preview. Completed plans remain exportable after Stop.

Multiple-choice reading uses ordinary visible DOM and accessible attributes only. Public upstream Perseus source inspection established the fieldset/Choose1legend/list/button aria-pressed layout; no private correctness or React state is accessed. Required legend suffix is recognized; ChooseN/all remains unsupported. Stem math excludes options. Hidden math is ignored, surrounding semantic text such as NOT/greater-than/approximately is not discarded, and all option states must be explicit. Choices are fingerprinted in order with the stem/ordinal so changes invalidate the saved delay and entry intent.

Any existing selection is preserved. After the normal10–30-second integer pause, one verified choice is selected and read back. CHECKING intent is saved first; a single injected atomic DOM action then revalidates the stem/options fingerprint, exact selected option and unique enabled Check before clicking once. A changed selected option or reordered options cannot slip between readback and Check. CAS comparisons are tri-state: exact true/false only when proved, null for unsupported/error. Null never counts as evidence that a distractor is wrong.
