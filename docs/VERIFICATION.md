# KUBLA KHAN 2.1.11 · optional local exact solver and queue recovery

The built-in restricted JavaScript solver could not answer every supported-looking expression. A rejected or unknown problem also paused the entire exercise lane, leaving the remaining queue idle. This release adds an optional free exact CAS helper and separate needs-review assignment recovery. It does not claim universal mathematics or unrestricted access to the owner's Chrome.

Built-in exact JavaScript runs first. If unsupported, an explicitly enabled helper receives only the expression and operation at fixed http://127.0.0.1:8765. The helper uses pinned SymPy1.14.0 and mpmath1.3.0 inside a private venv. It requires a random bearer token and an exact configured Chrome extension Origin; Host and client address must be loopback. Tokens remain in extension local storage and the private owner-only helper configuration, not diagnostics or release archives. Optional loopback permission is requested only by the popup Enable button. No remote question upload, paidAPI, LLM or helper model is involved.

The helper parses a limited safe expression grammar without eval or SymPy's arbitrary string parser. Each operation runs in a separate CPU/memory/time-limited process with request/response size limits and at most two workers. Its solve response is bound to the original request and exact verification method. Before entry, after actual MathQuill entry and again before Check, the extension calls exact verification that recomputes the ORIGINAL operation and compares the returned answer and actual observed field. Unknown or changed readback never authorizes Check. Factor answers must also have irreducible factor form. Multiple equation roots and unsupported formats pause/defer instead of guessing answer-list UI conventions.

Continue past blocked assignments defaults on. Recoverable unreadable/unsupported problems, preserved existing work, rejected or uncertain submissions and supported editor failures defer the WHOLE assignment, record a sanitized hashed review identifier/reason/phase, and open the next captured same-class assignment. Deferred work never increments completion. Unknown submission/entry intent is retained across fresh Starts and guards that assignment before page read; there is no blind automatic retry. Uncheck Continue to retain pause behavior. Scope, permission and closed-tab failures remain hard pauses. Stop prevents future actions, including delayed navigation. End UI says Queue processed · review needed when applicable.
